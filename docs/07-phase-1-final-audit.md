### W1 — the one warning (accepted, by design)

The `sm` button is **40 px** tall — the mockup's inline utility size. It passes WCAG 2.5.8 (24 px,
AA); 44 px is the AAA target and applies to primary actions, which are all 48–52 px.
**Rule: `sm` never carries a primary CTA.** Recorded here so it is a decision, not a defect.

## 2. What this run found — and fixed

The first pass of the extended gate produced 1 failure and 8 warnings. All were fixed in source;
none were waived.

| # | Finding | Root cause | Fix |
|---|---|---|---|
| 1 | **14 of 18 focusable elements had no visible focus ring** | No global focus treatment existed; the two components with a ring each defined their own | One `:focus-visible` rule in `globals.css` (`2px rust`, `offset 2`), gold on forest surfaces. Components no longer define rings. |
| 2 | Skip link missing | Never built | First tab stop on both pages, visible on focus, jumps to `#main-content` |
| 3 | Skip link had a **transparent** outline, then a 21 px box | My own `outline-none` + `not-sr-only` resetting padding | Removed `outline-none`; rebuilt the box after `not-sr-only` → 140 × 46 px with a real ring |
| 4 | Inputs used a second focus style (`ring-2 ring-rust/35`) | Component-level exception | Uses the global ring with `outline-offset-1`; one focus treatment in the system |
| 5 | **`#E5E7EB` (Tailwind gray-200) rendered on borders** | Preflight's default `border-color` is not a brand colour | `borderColor.DEFAULT` = the hairline token in the preset → stray greys impossible |
| 6 | 3 rendered colours outside the palette | Two were the root element's UA defaults (by-design), one a real leak | Scan now measures painted elements only; the real leak was #5 |
| 7 | No `og:image`, no canonical, no favicon | Never produced | `public/og.png` (1200×630, brand fonts, generated by `npm run og`), `public/favicon.svg`, canonicals on both routes |
| 8 | 1 dead export (`IconArrowLeft`) | Never used | Removed — 38/38 exports now referenced |
| 9 | `lucide-react` installed but never imported | Left over from scaffolding | Uninstalled; runtime deps are now exactly `clsx, next, react, react-dom, tailwind-merge` |

Two of my own harness checks were also wrong and were corrected (a wrapper element measured as
text; a `themeColor` regex flagging the *correct* API). A gate you cannot trust is worse than no
gate, so those fixes are part of the deliverable.

## 3. Security: the `npm audit` result and the Next 16 proof

`npm audit --omit=dev` reports **1 critical + 1 high**, both fixed only by `next@16`:

```
next     9.3.4-canary.0 – 16.3.0-preview.10   critical   → fix: next@16.4.3
postcss  <=8.5.22                             high       → (bundled inside next)
```

Next 14 is the end of its line — there is no patched 14.x. Because an unauthenticated RCE can
only be ignored with evidence, the upgrade was **built and tested, not assumed**:

1. Copied the app to a scratch dir (`apps/web16`, removed after the proof — it would only drift)
   and installed `next@16.4.3` + `react@19.2.0`.
2. Build failed with exactly three root-resolvable errors — recorded below.
3. After those three changes: **build ✓**, and the same gate on :3200 →
   **28 pass / 1 warn / 0 fail**, including 0 axe violations and 259/259 contrast pairs.

**The three changes a Next 16 upgrade needs** (this is the whole migration for this codebase):

| # | Symptom | Change |
|---|---|---|
| 1 | `Module not found: ../../brand/tailwind.preset` — Turbopack only resolves inside the project root | `next.config.mjs`: `turbopack: { root: new URL("../..", import.meta.url).pathname }` |
| 2 | `postcss-import: Failed to find '../brand/tokens.css'` — imports now resolve from the widened root | `app/globals.css`: `@import "../../../brand/tokens.css"` |
| 3 | CSS/Tailwind config had to load from the new root | `postcss.config.js` gains `postcss-import` path option; `tailwind.config.ts` keeps the same `../../brand/tailwind.preset` |

**Decision required from you:** (A) stay on Next 14.2.35 — every gate is green, but the framework
carries known unfixed RCE-class CVEs and the deployment needs network isolation; or (B) take the
upgrade — 3 file changes, gate-proven, removes both advisories.

**Recommendation: (B)**, and do it before Phase 5 rather than after, because a framework move is
cheapest while the component surface is 38 exports.
