1 · The honest headline

Neither codebase is an A2 platform today. The blueprint is a 26-CPT, 9-role, 3-layer WordPress system with a 14-week build. Setu is a 3-route NGO brochure site; A2 is a 1-route (plus shells) homepage with an exceptional design system. The real question is not "which is closer" but which is the better starting point for the 14 weeks ahead — and those have different answers depending on what you keep.
The answer is not either/or. Setu's WordPress layer is ~1,452 lines of production-shaped code the blueprint demands and A2 has none of: a mu-plugin, REST endpoints, an HMAC-verified Razorpay webhook, revalidation, and consent-gated publishing. A2's front-end is a token-enforced, accessibility-proven design system that Setu's generic green/terracotta UI cannot approach. The blueprint asks for exactly this split — “all business logic in a2-core; nothing in functions.php” — so the recommended path is Setu's PHP engine + A2's design system, not a rewrite of either.

3 · Where each one genuinely wins

Setu wins

WordPress engine & REST seam · payment loop with HMAC webhook · consent-gated publishing · compliance sections · PWA groundwork · a vetted, documented content-model discipline.

A2 wins

Design tokens, 4 font stacks, measured contrast · the 11-band editorial home · accessibility with proof (axe 40/0/0, 469 pairs, focus-ring gate) · 19/19 UX audit · reproducible sign-off harness.

Neither has it

26 CPTs · 9 roles + row-level scoping · 5 zones · the dashboard · the transparency ledger as a live query · CSR gating · compliance switches · Odia/Polylang · metrics governance.

4 · Three blockers that make this decision urgent

1. Setu ships claims the blueprint prohibits. Its header reads “80G & FCRA compliant” and its CTA promises “Instant 80G e-receipt”. Blueprint §13.2 lists exactly these under Prohibited until registered, and §13.1 gates them behind a hard admin switch that is default OFF. A2 Foundation is an unregistered voluntary initiative. Reusing Setu's copy or its receipt flow is a legal exposure, not a styling issue.
2. A2's content contradicts the blueprint's locked copy and term charter. The built H1 is “People / Planet / Possibility” and the metrics are “150K+ Lives Touched · 350+ Communities · 120+ Projects · 12+ Years”. Blueprint §6.1 locks the H1 to “Preserving Sacred Sanctity. Incubating Grassroots Dignity.” and §12 fixes the four counters to 150+ Metric Tons · 1,200+ Compliance Hours · 100% Direct Banking · 60+ Children Sustained — rendered only from the metric subsystem, never hand-typed. A2's counters are hand-typed in content/home.ts. Also prohibited by §0.2/§4.2: “Donate” should be Voluntary Contribution. The A2 mockup is a generic NGO design; the blueprint is a specific institution — the front-end can host either, but the copy layer must be replaced wholesale.
3. Both differ from the blueprint's mandated stack. §11.1 requires a WordPress block theme (a2-ekamra) with theme.json tokens and business logic in a2-core. Setu is headless — it explicitly accepts that “editors cannot build new page layouts themselves”, which conflicts with a block theme but is defensible if the client agrees. A2 is Next.js with no WordPress at all, so its 2-day “Phase 6 WordPress content model” would have to grow into the full §8 data model. Its own README already states the hybrid PHP fallback.

5 · Recommendation

  1. Take Setu's PHP layer as the seed of a2-core. Keep the mu-plugin architecture, the REST seam, the HMAC webhook pattern and the consent gate. Discard its three CPTs' field shapes only where the blueprint's 26 override them. This is the single largest saving available — roughly §11.1–11.2, the highest-weight row, at 35% already rather than 5%.
  2. Take A2's design system, not Setu's UI. But retarget it to the blueprint's Khandolite tokens: terracotta #B84A39, marigold #F2B705, charcoal #262626, cream #FDFBF7, Playfair/Lora + Plus Jakarta Sans, Noto Serif/Sans Oriya. A2's tokens are close in spirit (rust #AB3D24, gold #C9A961, cream #FBF7F0) but are mockup-derived, not spec-derived. Its token-parity check makes this a one-file change plus a re-audit — which is exactly what that harness exists for.
  3. Replace A2's entire copy layer against §6.1/§7/§12/§4.2 before any further build. Route the built components at the seven Sacred Pillars and the four governed metrics; drop the generic “Lives Touched” band rather than restyling it.
  4. Then build what neither has, in blueprint order: CPTs + roles + zones (§8–9) → dashboard + ledger (§6.4–6.5, §12) → contributions with compliance switches (§13) → CSR gating (§6.6) → Odia/Polylang (§4.2, §7).
  5. Keep A2's validation harness regardless of stack. axe 40/0/0, 469 contrast pairs, the keyboard focus-ring gate, 17 fidelity rows and the one-command sign-off are contractual under §18.11 and do not exist on the Setu side at all.

6 · If you must pick exactly one

Stated plainly, because the two score differently depending on the axis.

AxisWinnerWhy
Adaptability to the blueprint as a platformSetu It already has WordPress, a plugin seam, roles-ready CPTs and a payment loop. A2 has none of the backend; its path to §8 is build-from-zero.
Adaptability on the public Layer 1 experienceA2 The blueprint's L1 is “cinematic, editorial, bilingual”. A2's is measurably editorial and accessible; Setu's is a competent generic NGO template.
Adaptability as this project's live deliverableA2 25% vs 17% weighted, nothing contradicting the spec in its code, a reproducible gate, and a sign-off artefact the client can approve today.
Risk of legal/compliance harm if adopted as-isA2 (far safer) Setu's 80G/FCRA claims are prohibited for an unregistered entity. A2 is neutral — it has no receipt language to retract.
Bottom line. On the blueprint as written, Setu is the more adaptable engine and A2 is the more adaptable product. Neither adapts alone, and the gap to the blueprint is large on both sides (17% / 25%). The cheapest credible route to a 14-week build is Setu's WordPress core under A2's design system, with A2's mockup copy replaced by the blueprint's locked copy before anything else ships.
